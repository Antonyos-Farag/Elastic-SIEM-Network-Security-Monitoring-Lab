# Contributing

Thanks for helping make this lab clearer, safer, and reproducible.

## Useful contributions

- Correct inaccurate architecture or protocol descriptions.
- Add sanitized, reproducible setup and validation evidence.
- Contribute tested detection content with field mappings and false-positive notes.
- Improve accessibility, diagrams, and troubleshooting guidance.

## Before submitting

1. Keep changes scoped and explain their purpose.
2. Label content as reported, documented, newly tested, or proposed.
3. Never present generated illustrations or proposed configurations as lab evidence.
4. For tested changes, include versions, prerequisites, expected/actual results, and limitations.
5. Redact secrets and sensitive infrastructure details; see [SECURITY.md](SECURITY.md).
6. Check Markdown links and SVG validity using `python3 scripts/check_docs.py`.
7. Do not add large captures, VM images, binaries, datasets, or raw reports. Prefer reviewed excerpts.

Use the [evidence template](examples/evidence-record.md) for new test results. Explain any departure from the source documentation rather than silently rewriting history.

## Licensing

No project license has been selected. Do not assume open-source reuse permission from public visibility, and do not contribute material you lack permission to share. Vendor software remains subject to its own licenses.
